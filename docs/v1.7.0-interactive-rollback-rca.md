# v1.7.0 Interactive Rollback RCA

## Scope

This investigation covers the failed interactive v1.8.2 to v1.7.0 rollback first observed on the repeatedly used development host on 2026-07-12 and the independent Hyper-V ReleaseLab reproduction completed on 2026-07-13.

No NSIS configuration or historical installer asset was changed during the RCA.

## Original Host Observation

On the original host, v1.8.2 uninstalled successfully and retained user configuration, but two interactive v1.7.0 reinstall attempts appeared to start without persisting the install directory or uninstall registration. A silent `/S` v1.7.0 install then restored the files and registration. A residual vendor key and the host's repeated prior installer activity prevented reliable attribution.

That observation was real at the filesystem and registry level, but the environment was not isolated and could not prove an installer defect.

## Independent ReleaseLab Matrix

Every case restored `BASE-00A-Clean-Windows-LocalAdmin` independently and used the verified historical assets.

| Case | Scenario | Result |
|---|---|---|
| A | Clean Windows -> interactive v1.7.0 install and launch | PASS |
| B | Clean Windows -> silent v1.7.0 install and launch | PASS |
| C | v1.7.0 + Profile -> interactive historical v1.8.2 upgrade | PASS |
| D | historical v1.8.2 uninstall -> interactive v1.7.0 rollback | PASS |
| E | historical v1.8.2 uninstall -> silent v1.7.0 rollback | PASS |

Case D is decisive: v1.7.0 files, uninstall registration, version, configuration, and the retained Profile were present after the interactive rollback. Case E independently verified the silent recovery path.

## Conclusion

- Exact original-host root cause: not recoverable from the contaminated host state.
- Release attribution: the failure is not reproducible on clean, independently restored Windows and is not evidence of a v1.7.0 or v1.8.2 installer defect.
- Classification: original-host state contamination or observation-context failure.
- Installer blocker: cleared by clean-VM counter-evidence.
- Historical assets: remain RCA-only and must not be published as the current release candidate.

Raw VM evidence remains under Git-ignored `artifacts/release-lab/historical-v1.8.2/`; the committed SHA256 index is in `docs/release-lab-v1.8.2.md`.
