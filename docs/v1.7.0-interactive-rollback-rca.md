# v1.7.0 Interactive Rollback RCA

## Scope

This investigation documents the failed interactive v1.8.2 to v1.7.0 rollback observed on 2026-07-12. It does not modify NSIS configuration or either release asset.

## Environment limitation

- Clean Windows VM or restorable snapshot used: **No**
- Test host: the existing Windows development machine after repeated prior install/uninstall verification
- Consequence: the failure is a valid release-blocking observation, but it is not sufficient to attribute the root cause to v1.8.2 or v1.7.0.

## Observed sequence

1. The machine started with v1.7.0 installed and DevEnv Manager closed.
2. Interactive v1.8.2 setup detected v1.7.0 and selected `Uninstall before installing`.
3. The user completed the nested uninstall and installation dialogs.
4. v1.8.2 launched successfully, loaded the Tauri backend, retained the configured root, and displayed the existing Profile count of 1.
5. v1.8.2 was uninstalled while application data was retained.
6. The v1.8.2 program directory and Add/Remove Programs entry were absent. Settings remained 950 bytes with SHA256 `8fd1d16130effb597ea451b0f93beb344b4e496bec98e51e5c118028dc3c2235`; Profile count remained 1.
7. A residual `HKCU\Software\weidonglang\DevEnv Manager` key still contained the prior install directory and installer language.
8. Interactive v1.7.0 setup reported that a newer version was installed even though the program directory and uninstall entry were absent.
9. After selecting `Do not uninstall`, v1.7.0 launched, but shell inspection showed that its reported image path no longer existed and no uninstall entry had been created.
10. A second interactive `Add/Reinstall components` attempt reproduced the same result: the process ran, but the install directory and uninstall entry were absent.
11. The process was closed. Running the same verified v1.7.0 installer with `/S` returned exit code 0, persisted all three program files, restored the v1.7.0 uninstall entry, and launched successfully.
12. After the restored application exited, the v1.7.0 files and uninstall entry remained present. Settings hash and Profile count were unchanged.

## Findings

### Confirmed

- The failure was not only a desktop-automation observation error. Independent filesystem, process, version-resource, and uninstall-registry checks showed that the interactive install did not persist.
- v1.8.2 uninstallation retained user configuration and removed its primary program directory and uninstall entry.
- A vendor install-directory marker remained under `HKCU\Software\weidonglang\DevEnv Manager`.
- Silent v1.7.0 installation was a successful recovery path on the same host.

### Not yet proven

- Whether the residual vendor key alone causes the version comparison or failed persistence.
- Whether the interactive installer exited early, launched from temporary files, or was affected by a delayed cleanup operation.
- Whether the behavior reproduces on a clean VM.
- Whether the defect belongs to the v1.7.0 installer, the v1.8.2 uninstaller, or their interaction.
- Whether elevation context or a pending-reboot marker contributed.

## Required clean-VM follow-up

For each of the five required cases, capture installer exit code, process tree, install directory before and after process exit, complete file list, ARP entries, uninstall registry values, shortcuts, NSIS logs if available, Windows event logs, UAC state, user/elevation context, and pending-reboot state. Revert the VM snapshot between cases.

## Conclusion

- Root cause: **root-cause unresolved**
- Owner component: installer lifecycle and NSIS version/uninstall detection, pending clean-VM attribution
- Requires v1.8.2 installer change: **unknown; do not modify or invalidate assets until clean-VM evidence attributes the defect**
- Current asset status: hashes remain valid and assets remain protected, but release is blocked by the failed required rollback gate
